# 업로더 사용 안내

상태: Windows x64 개발 버전. 로그인·전송 코드는 구현했지만 실제 Windows·Blob·Discord 검증과 서버 배포는 남아 있다. 서버 주소는 빌드 시 고정되며 기본값은 없다. 다운로드 아티팩트의 `provenance.txt`에서 연결 대상을 확인한다. 서버의 `DESKTOP_UPLOADER_ENABLED`가 켜져 있어야 연결할 수 있다.

1. [빌드 안내](development.md)에 따라 만든 exe를 실행한다. 설정은 `%LOCALAPPDATA%/LLVY/Uploader/` 아래 origin별 공간에 저장한다. exe가 달라도 같은 Windows 사용자/origin은 한 인스턴스만 실행한다.
2. 저장한 경로, Windows 문서 폴더, 고정 드라이브의 알려진 설치 후보를 확인한다. 여러 후보가 있으면 `리플레이 폴더`에서 고른다. `폴더 선택`으로 복사한 폴더나 빈 폴더도 사용할 수 있다. 미검증 LoL 설정 파일은 읽지 않는다.
3. `게임 ID`에 `KR-1234567890` 또는 숫자 경기 번호를 입력하고 `파일 찾기`를 누른다. 공백·줄바꿈·쉼표·세미콜론으로 최대 100개를 구분한다. Riot ID `이름#태그`는 경기 번호가 아니다.
4. 파일명·크기·수정 시각을 확인한다. 복수 후보는 해당 행에서 `선택한 후보 사용`을 누른다. 같은 파일은 한 번만 업로드한다. `로컬 다운로드 필요`는 탐색기에서 `항상 이 장치에 유지` 후 다시 찾는다. 탐색은 파일 내용을 읽거나 다운로드를 시작하지 않는다.
5. `LLVY 로그인`을 누르고 브라우저에서 계정·권한·수명을 확인한 뒤 `연결 허용`을 누른다. 관리자/오너만 연결할 수 있다. `로그인 유지`는 기본 꺼짐이다.
6. 선택 수와 계정/전체 최소 잔여 예약 수·확인 시각을 확인한다. 계정 10회·전체 50회/24시간을 웹과 공유한다. 중복·실패도 예약을 소비하며 표시 후 다른 클라이언트가 사용할 수 있다. 새 예약 수가 초과하면 입력 ID를 줄여 다시 찾는다. 이미 예약을 시도한 항목은 같은 기기 연결에서 잔여 0에서도 같은 키로 복구하며, 혼합 선택에서는 새 항목만 보류한다.
7. `업로드`는 선택 파일을 한 개씩 예약·전송·처리한다. 창을 멈추지 않고 상태·진행률을 갱신한다. 실패한 파일 행을 선택하고 `실패 항목 다시 시도`를 누르면 같은 예약의 상태부터 확인한다. 이미 성공한 작업은 재전송하지 않는다. 예약 전 파일 변경 오류가 나면 다시 찾아 선택하여 최신 파일 정보로 시도할 수 있다. 이미 예약을 시도한 항목은 원래 정보와 키를 유지한다. 완료·중복 성공 행을 더블 클릭하면 해당 경기 페이지를 연다.

## 연결 보관과 해제

브라우저 승인 후 상태 조회가 실패하거나 취소되면 `연결 정보 있음`으로 표시한다. `LLVY 로그인`을 다시 누르면 보관 중인 연결로 계정·한도 조회를 재시도한다. 새 브라우저 승인은 기존 연결이 없을 때만 시작한다.

임시 연결은 최대 12시간이고 정상 종료 시 최대 2초 회수를 시도한다. crash·오프라인 종료로 남은 연결은 브라우저 기기 관리에서 해제하거나 다음 승인에서 임시 연결을 명시적으로 교체한다. 활성 연결은 계정 합계 5개다.

로그인 유지는 최대 30일이다. refresh만 Windows 사용자 범위 DPAPI로 암호화해 원자적으로 저장한다. access/verifier는 메모리에만 둔다. 갱신 응답 유실·복호화·새 토큰 저장 실패는 재로그인이 필요하며 이전 refresh를 자동 재전송하지 않는다. 처리 요청 전 access 유효기간을 2분 이상 확보하도록 갱신하며, 기기 절대 만료가 가까워 충분한 수명을 얻지 못하면 재로그인을 요구한다. USB로 로그인 정보를 옮기는 기능은 없다.

`로그아웃`은 서버 연결 해제를 시도하고 로컬 비밀을 지운다. 서버 해제 실패는 따로 표시한다. 서버 해제 대기 중 취소하더라도 이미 수행한 로컬 로그아웃·기록 삭제와 화면 상태는 유지한다. 브라우저의 `/desktop/devices`에서도 본인 기기를 해제할 수 있다. `로컬 기록 삭제`는 앱 설정과 로컬 비밀을 지우지만 실행 중 잠금 파일은 유지한다.

예약은 생성 당시의 기기 연결에 속한다. 로그아웃·인증 만료 등으로 연결이 해제되거나 바뀌면 이전 예약이 있는 작업과 파일 선택을 비운다. 이전 서버 결과를 확인한 뒤 `파일 찾기`로 다시 선택해야 한다. 새 연결의 업로드는 새 예약 한도를 사용하며 이전 예약의 복구로 취급하지 않는다.

## 불확실한 결과

PUT 응답을 받지 못하면 같은 uploadId/nonce로 서버에 확인한다. 서버가 정확히 파일 부재를 확인하기 전에는 overwrite하지 않는다. 처리 응답 유실은 상태 조회로 복구한다. claim 만료나 실행 중단으로 결과가 확정되지 않으면 `결과 불명확`을 표시한다. 한도 429 또는 인증/권한 회수는 큐를 멈춘다.

`취소`나 창 닫기는 현재 네트워크·탐색 작업을 중단한다. 취소된 자동 폴더 탐색은 폴더 선택창을 열지 않으며 기존 폴더·파일 선택을 유지한다. 취소된 파일 검색 결과도 적용하지 않는다. 직접 선택해 저장한 폴더와 이미 완료한 연결 변경은 유지한다. 이미 서버에 도착한 작업은 계속 처리될 수 있으므로 완료를 가정하지 않는다. 큐와 예약 복구 정보는 현재 프로세스 메모리에만 있어 앱 종료 후 자동 재개하지 않는다. 원본 리플레이는 수정·이동·삭제하지 않는다.
