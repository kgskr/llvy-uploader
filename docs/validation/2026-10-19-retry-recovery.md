# 예약 복구와 명시적 새 시도 검증

확인일: 2026-10-19. 상태: 로컬 Go 구현·회귀 검사 및 Windows 교차 컴파일. 실제 Windows UI·Blob·Discord·운영 배포는 검증하지 않았다.

## 변경과 이유

- 기존 예약의 상태·process 확인과 유실된 예약 응답 복구를 로컬 파일 접근보다 먼저 수행한다. 서버에 정상 객체가 있으면 원본 파일 이동·삭제·변경과 무관하게 처리를 마칠 수 있다. `object_not_uploaded`로 부재가 확정된 경우에만 원본 정보·hash를 확인하고 재전송한다.
- `실패 항목 다시 시도`는 기존 예약을 먼저 복구한다. 확정 실패·만료·결과 불명확일 때만 새 예약 1회 소비와 중복 가능성을 알리고, 기본값이 아니요인 확인창을 UI 스레드에서 표시한다. 확인 후 기존 결과·기기·최신 한도를 다시 검사한다.
- 자동 업로드·복구는 새 키를 만들지 않는다. 취소된 새 시도도 이미 예약을 시도했다면 새 키를 보존한다. 인증·네트워크·저장소 오류와 처리 중/성공 결과는 새 예약을 허용하지 않는다.
- process 오류 뒤 상태 조회에서 받은 권한·한도 오류를 보존하여 큐 중단 판단에 사용한다.

## 검사

Go 1.27.0에서 전체 48개 테스트가 통과했으며 다음 검사를 통과했다. 하위 시나리오는 테스트 수에 중복 집계하지 않았다.

```bash
go test ./...
go vet ./...
go test -race ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -o /tmp/llvy-uploader-review.exe ./cmd/llvy-uploader
openspec validate --all --strict
git diff --check
```

영구 회귀는 `internal/desktop/queue_recovery_test.go`와 `internal/ui/retry_test.go`에 있다. 서버 응답은 mock이며 실제 Blob·Discord를 호출하지 않는다. 원본 이동·삭제·내용 변경 후 복구, 확정 부재 후 hash 검증, 저장소 장애의 부재 오판 방지, 잔여 0에서 유실 예약 복구, 확정 결과별 새 시도 허용, 확인 전·후 한도/기기/인증/취소 경계, 새 시도의 응답 유실 시 키 보존을 검사한다.

Windows 교차 빌드는 컴파일 검사다. 네이티브 확인창 표시·기본 버튼·모달 동작·취소의 실제 Windows 실행을 의미하지 않는다. Windows CI·실제 사용자 PC·Blob·Discord 검증과 운영 활성화가 남아 있으므로 기능 change는 열린 상태로 유지한다.

## 계약과 문서

서버 API·JSON 계약·고정 원본 revision과 체크섬은 변경하지 않았다. 서버 코드는 이번 수정 대상이 아니다. README·사용 안내·활성 OpenSpec과 위키의 업로더·구조·프로젝트 요약, 출처·변경 기록을 갱신했다.

## 추가 경계와 최종 검토

확인창을 담은 결과가 전달 대기 중일 때 취소해도 UI에서 확인창을 억제한다. 이미 생성한 새 예약의 식별자와 완료된 인증 변경은 보존한다. 예약 전 파일 검사 실패 항목은 재검색한 정보를 반영하고 최초 예약 전에 한도를 검사하며, 예약 시도 항목의 원래 정보는 유지한다. 독립 코드 검토를 수정 후 반복했고 최종 두 검토에서 추가 확정 결함은 없었다.

Windows 대상 vet와 로컬 문서·위키의 상대 링크/앵커 76개도 확인했다. 이 검토는 실제 Windows 모달·IME·DPI·외부 업로드 실행을 대체하지 않는다.
